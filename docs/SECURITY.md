# Безопасность

Что защищаем, как, и что сознательно не закрыто. В документе только то, что проверено; планы помечены.

## Что защищаем

Один публичный VPS (1 ГБ RAM) с прокси приложения MaxApoc: прокси хранит токены GitHub, ключи LLM-шлюзов и закрытый ключ TLS-сертификата сервера. Владелец один. Главные угрозы: подбор доступа к серверу из интернета, утечка секретов (через репозиторий, вывод, логи, переменные окружения), случайно открытые порты, неконтролируемые изменения сервера.

## Доступ к серверу

- **SSH — только по ключу:**
  - вход по паролю, под root и keyboard-interactive отключены кодом (`sshd_config.d/00-hardening.conf`);
  - конфиг проверяется (`sshd -t`) до применения;
  - рабочий сервер — с 28.10.2026, проверено `sshd -T` и попытками входа по паролю и под root.
- SSH с ограничением частоты подключений (`ufw limit`: 6 за 30 секунд с адреса).
- **Отдельный пользователь для работы:**
  - права root через sudo **с паролем**;
  - не входит в группу `docker` (доступ к Docker равен root).
- Запасной вход — консоль хостера (проверяется перед работами с доступом).

## Деплой из CI

Цель: утечка того, чем пользуется CI, не даёт доступа к серверу ([ADR-016](DECISIONS.md#adr-016)).

- **Отдельный пользователь `maxapoc-deploy`:**
  - пароль заблокирован;
  - не в группе `docker`;
  - без общего sudo.
- **Ключ с ограничениями** в `authorized_keys`:
  - только ключ CI; у тестовой среды и рабочего сервера ключи разные;
  - `restrict` — без терминала, пробросов портов и агента;
  - принудительная команда — что бы ни попросил клиент, запускается скрипт-фильтр.
- **Скрипт-фильтр:**
  - пропускает только `status` и `deploy sha256:<64 символа 0-9a-f>`;
  - шаблон проверяет строку целиком: пробел, `;`, `-`, перевод строки не проходят;
  - каждое решение — в журнал с адресом клиента; непроверенный ввод — экранированным (`printf '%q'`), чтобы переводом строки нельзя было подделать запись.
- **sudo на один скрипт:**
  - `/etc/sudoers.d/maxapoc-deploy` (`0440`, проверка `visudo -cf`) разрешает только `maxapoc-deploy-run`;
  - скрипт — `root`, `0700`: пользователь деплоя его не изменит и не прочитает;
  - скрипт повторно проверяет формат; имя образа зашито — клиент присылает только digest, чужой реестр не подставить.
- **Окружение GitHub `production`:**
  - секреты деплоя (ключ, адрес, `known_hosts`) — только в окружении;
  - правило веток — только `main`: запуск с другой ветки отклоняется до первого шага, секреты не выдаются;
  - задача деплоя — `contents: read`, `concurrency` без отмены;
  - секреты передаются шагам через `env:`, а не вставкой в текст команд.
- **Ключ хоста — по доверенному каналу:**
  - строка `known_hosts` прочитана через уже проверенное SSH-подключение, отпечаток сверен;
  - в CI `StrictHostKeyChecking=yes`, без `ssh-keyscan`;
  - после переустановки сервера новый отпечаток сверяется через консоль хостера.
- **CI не знает секретов приложения:** `.env`, сертификаты, токены и ключи шлюзов доставляет только Ansible.

**Проверено:**
- вход без команды — нет терминала и отказ;
- `status; id`, неверный и многострочный digest — отказ;
- проброс порта — отклонён;
- ключ тестовой среды на рабочем сервере (`IdentitiesOnly=yes`) — отказ;
- `sudo -l` — одна команда;
- запуск с неразрешённой ветки — отклонён окружением, секреты в логе замаскированы.

## Сеть

- **Файрвол ufw, default-deny для входящих, задано кодом** (роль `security`; рабочий сервер — с 28.10.2026):
  - SSH разрешён отдельным правилом;
  - остальные порты — списком в инвентаре, с назначением каждого (комментарий в правиле ufw);
  - агент Zabbix хостера — только с адресов хостера.
- **Порты, опубликованные Docker, обходят правила ufw** (проверено экспериментом: порт без адреса публикации доступен снаружи при закрытом ufw). Поэтому сервисы, которые не должны быть публичными, публикуются только на конкретный адрес:
  - интерфейсы Prometheus, Alertmanager, Grafana — на `127.0.0.1`, доступ через SSH-туннель;
  - метрики прокси — внутри сети Docker без публикации; на рабочем сервере дополнительно на адресе WireGuard (для стека `hobot-metrics`).
- Наружу опубликован только порт прокси 8443 (TLS).

## Секреты

- **Ansible Vault:**
  - в репозитории только шифротекст;
  - у тестовой среды и рабочего сервера **разные пароли** vault;
  - пароли — в файлах вне git (`0600`) и в менеджере паролей.
- **`no_log`** у задач с секретами: значения не попадают в вывод Ansible, в том числе при `--diff`. Логи запусков не хранятся в git.
- **Контейнерам секреты передаются файлами, где приложение это умеет:**
  - токен Telegram (Alertmanager) и пароль Grafana — файлы `0400`, владелец — пользователь процесса в контейнере;
  - их нет в `docker inspect` и в окружении процессов (проверено);
  - прокси читает секреты из `.env` (`root`, `0600`).
- Сверка секретов с сервером — по хешам, без вывода значений.
- **Адреса и имена инфраструктуры — в vault:** адреса серверов, пользователь и ключ SSH, адреса Zabbix хостера, хранилище копий, адреса приватных репозиториев. Открытый инвентарь не раскрывает инфраструктуру.
- **Токен реестра образов на сервере:**
  - только на чтение (classic PAT `read:packages`), срок 90 дней, напоминание за 7 дней;
  - свой у каждого окружения, в vault;
  - на сервере — в `/root/.docker/config.json` (`0600`).
- **Тестовая среда не хранит секретов рабочего сервера:** свой CA, свой бот и чат для оповещений, свой пароль репозитория копий.
- **Корень доверия — менеджер паролей** (пароли vault, `ca.key`, пароли копий, токены): у его базы есть копия на втором компьютере.

## Прокси

- **TLS с собственным CA:**
  - приложение доверяет только ему;
  - **закрытый ключ CA на сервере не хранится**;
  - сертификат сервера выпускается вне сервера и доставляется через vault.
- **Контейнер прокси** (проверено на рабочем сервере, `docker inspect`: `ReadonlyRootfs`, `CapDrop`, `SecurityOpt`, `Memory`, `PidsLimit`):
  - процесс **не от root** (uid 1000; рабочий сервер — с 28.10.2026, до этого работал от root);
  - файловая система только для чтения;
  - все capabilities сняты, `no-new-privileges`;
  - лимиты памяти (96 МБ) и числа процессов (64).
- Конфигурация шлюзов и суточные потолки расходов (`gateways.json`) подключены в контейнер только для чтения; источник — репозиторий проекта.
- Контейнер запускается по **digest** образа (`…@sha256:…`), а не по тегу: подменить содержимое под той же ссылкой нельзя.

## Резервные копии

- **Шифрование на стороне сервера** (restic): хранилище S3 видит только шифротекст.
  - у каждого окружения свой репозиторий и свой пароль;
  - пароль — в vault и в менеджере паролей, ключи S3 — в vault;
  - на сервере — `/etc/restic` (`0700`), `env` (`0600`), `password` (`0400`), владелец root.
- **Копия домой** (раз в месяц) — на управляющей машине: ключи и пароль в `~/.config/restic` (`0600`), репозиторий — там же, где уже лежат пароли vault.
- Бакет приватный, с версионированием (неактуальные версии — 30 дней).
- **Учения не задевают рабочий сервер:**
  - копия восстанавливается в отдельный каталог;
  - пароль рабочего сервера — во временном файле (`0400`), после учений `shred -u`; восстановленные данные удаляются;
  - WireGuard, x-ui и Alertmanager `hobot-metrics` из копии в тестовой среде не запускаются: ключ туннеля, бот x-ui и настройки оповещений принадлежат рабочему серверу.
- Ключи WireGuard (`vps_private.key`, `wg0.conf`) — `0600` (исправлено; копия сохраняет права, поэтому исправление переживёт восстановление).

## Цепочка поставки

- Пакеты Docker — из официального репозитория с проверкой подписи (`signed-by`); версии закреплены и удерживаются от обновления.
- Образы стека мониторинга — с закреплёнными версиями (`prom/prometheus:v3.13.2`, `prom/alertmanager:v0.28.1`, `grafana/grafana:13.2.0`).
- **Образ прокси:**
  - собирается только в CI, после тестов, из коммита (метка `revision`);
  - публикуется в приватный GHCR с правами задачи `packages: write`;
  - на сервере не собирается.
- На серверы попадают только файлы из ветки `main` (чистый клон, правки в нём останавливают запуск), а не из рабочей копии.
- Официальные действия GitHub (`actions/*`, `docker/*`) закреплены по основной версии (см. ограничения).

## Известные ограничения и принятые риски

| Что | Почему так | Чем смягчено |
|---|---|---|
| Панель x-ui (VPN) открыта в интернет | нужна для управления VPN без туннеля | случайный путь, сложный пароль, TLS (принятый риск) |
| `APP_KEY` вшит в APK и извлекается из него | особенность клиентского ключа | отсекает случайные запросы; от целенаправленного использования защищают суточные потолки и лимиты на прокси |
| Токен Telegram попадает в лог Alertmanager при ошибке сети (часть URL Bot API) | поведение Alertmanager | лог доступен только root; у тестовой среды отдельный бот |
| Файлы паролей vault на управляющей машине открытым текстом | так работает `vault_identity_list` | права `0600`, каталог вне git; разделение паролей защищает при утечке одного файла, но не при доступе к машине |
| CA не перевыпускался после хранения `ca.key` на сервере | признаков компрометации нет; перевыпуск = пересборка приложения у всех | ключ вынесен с сервера, резервные копии хостера, сделанные до выноса, удалены |
| Прокси читает секреты из `.env`, а не из файлов | нужно изменение приложения | `.env` — `root`, `0600`; сервер без лишних пользователей |
| Роль ufw только добавляет правила | особенность роли | удаление — ручной шаг в плане работ |
| Наблюдаемость MaxApoc на рабочем сервере зависит от стека `hobot-metrics` | памяти не хватает на второй стек | см. [ADR-006](DECISIONS.md#adr-006); копия правил оповещений синхронизируется вручную |
| Кто может запушить в `main`, тот управляет продом | так устроен автодеплой; защита веток для приватного репозитория — только на платном тарифе | 2FA аккаунта, один участник с правом записи; ключ CI ограничивает ущерб ([ADR-016](DECISIONS.md#adr-016)) |
| Classic-токен реестра читает все пакеты аккаунта | GitHub Packages не принимает fine-grained токены | только чтение, срок 90 дней, свой у окружения; сейчас пакет один. Улучшение — машинный аккаунт с доступом только к пакету |
| Токен реестра на сервере в base64 (`/root/.docker/config.json`) | так хранит `docker login` | `0600`, только чтение |
| Действия GitHub закреплены по основной версии, а не по хешу коммита | компромисс простоты; только официальные `actions/*` и `docker/*` | права задач минимальны; сборочная задача видит только `GITHUB_TOKEN` |
| Базовый образ `node:22-alpine` — передвигаемый тег | обновления безопасности базового образа приходят без правок | каждый образ проходит тесты; на сервер едет по digest |
| Root на рабочем сервере = пароль и ключи копий (чтение, удаление, подмена) | копия делается на сервере | версионирование бакета (30 дней) — от ошибки; от атакующего — домашняя копия, отставание до месяца |
| Ключ S3 один на бакет | хостер не выдаёт отдельных ключей | тестовая среда может удалить копии рабочего сервера, но не расшифровать (пароли разные); тестовая виртуальная машина (ВМ) недоступна из интернета |
| Ежемесячная копия домой — ручной шаг | выбран простейший вариант | порядок и проверка возраста копии — в OPERATIONS; улучшение — таймер на управляющей машине |
| Токен Telegram в адресе запроса при оповещении о сбое копии (`curl`) | так устроен Bot API | процесс root, кратковременно; скрипт не выводит адрес в журнал |
| Поздний сбой после деплоя ловят оповещения, а не CI | один пользователь, цена кода выше риска | [ADR-022](DECISIONS.md#adr-022): ~11–20 мин до оповещения |

## Публикация репозитория

- В открытом коде и в истории репозитория нет адресов серверов, имён приватных репозиториев и секретов: всё это — в vault (раздел «Секреты»). Проверено поиском по всей истории перед публикацией.
- **gitleaks** (закреплённая версия, проверка контрольной суммы) проверяет всю историю при каждом пуше и pull request.
- Не сделано: проверка секретов до коммита (pre-commit) на управляющей машине.
