# Безопасность

Что защищаем, как, и что сознательно не закрыто. В документе только то, что проверено; планы помечены.

## Что защищаем

Один публичный VPS (1 ГБ RAM) с прокси приложения MaxApoc: прокси хранит токены GitHub, ключи LLM-шлюзов и закрытый ключ TLS-сертификата сервера. Владелец один. Главные угрозы: подбор доступа к серверу из интернета, утечка секретов (через репозиторий, вывод, логи, переменные окружения), случайно открытые порты, неконтролируемые изменения сервера.

## Доступ к серверу

- SSH: **вход только по ключу**; вход по паролю, под root и keyboard-interactive отключены кодом (`sshd_config.d/00-hardening.conf`); конфиг проверяется (`sshd -t`) до применения. Рабочий сервер — с 28.10.2026, проверено `sshd -T` и попытками входа по паролю и под root.
- SSH с ограничением частоты подключений (`ufw limit`: 6 за 30 секунд с адреса).
- Работа на сервере — под отдельным пользователем, права root через sudo **с паролем**. Пользователь не входит в группу `docker` (доступ к Docker равен root).
- Запасной вход — консоль хостера (проверяется перед работами с доступом).

## Сеть

- **Файрвол: ufw, default-deny для входящих, задано кодом** (роль `security`; рабочий сервер — с 28.10.2026). SSH разрешён отдельным правилом; остальные порты перечислены списком в инвентаре с назначением каждого (комментарий в правиле ufw); агент Zabbix хостера — только с адресов хостера.
- **Порты, опубликованные Docker, обходят правила ufw** (проверено экспериментом: порт без адреса публикации доступен снаружи при закрытом ufw). Поэтому сервисы, которые не должны быть публичными, публикуются только на конкретный адрес:
  - интерфейсы Prometheus, Alertmanager, Grafana — на `127.0.0.1`, доступ через SSH-туннель;
  - метрики прокси — внутри сети Docker без публикации; на рабочем сервере дополнительно на адресе WireGuard (для стека `hobot-metrics`).
- Наружу опубликован только порт прокси 8443 (TLS).

## Секреты

- **Ansible Vault:** в репозитории только шифротекст; у тестовой среды и рабочего сервера **разные пароли** vault. Пароли — в файлах вне git (`0600`) и в менеджере паролей.
- Задачи с секретами помечены `no_log`: значения не попадают в вывод Ansible, в том числе при `--diff`. Логи запусков не хранятся в git.
- **Контейнерам секреты передаются файлами, где приложение это умеет:** токен Telegram (Alertmanager) и пароль Grafana — файлы `0400`, владелец — пользователь процесса в контейнере; их нет в `docker inspect` и окружении процессов (проверено). Прокси читает секреты из `.env` (`root`, `0600`).
- Сверка секретов с сервером — по хешам, без вывода значений.
- Тестовая среда не хранит секретов рабочего сервера: свой CA, свой бот и чат для оповещений.

## Прокси

- TLS с собственным CA: приложение доверяет только ему. **Закрытый ключ CA на сервере не хранится**; сертификат сервера выпускается вне сервера и доставляется через vault.
- Процесс прокси в контейнере работает **не от root** (uid 1000; рабочий сервер — с 28.10.2026, до этого работал от root), файловая система контейнера только для чтения, все capabilities сняты, `no-new-privileges`, лимиты памяти (96 МБ) и числа процессов (64). Проверено на работающем контейнере рабочего сервера (`docker inspect`: `ReadonlyRootfs`, `CapDrop`, `SecurityOpt`, `Memory`, `PidsLimit`).
- Конфигурация шлюзов и суточные потолки расходов (`gateways.json`) подключены в контейнер только для чтения; источник — репозиторий проекта.

## Цепочка поставки

- Пакеты Docker — из официального репозитория с проверкой подписи (`signed-by`); версии закреплены и удерживаются от обновления.
- Образы стека мониторинга — с закреплёнными версиями (`prom/prometheus:v3.13.2`, `prom/alertmanager:v0.28.1`, `grafana/grafana:13.2.0`).
- Код прокси доставляется на сервер по белому списку файлов.

## Известные ограничения и принятые риски

| Что | Почему так | Чем смягчено |
|---|---|---|
| Панель x-ui (VPN) открыта в интернет | нужна для управления VPN без туннеля | случайный путь, сложный пароль, TLS (принятый риск) |
| `APP_KEY` вшит в APK и извлекается из него | особенность клиентского ключа | отсекает случайные запросы; от целенаправленного использования защищают суточные потолки и лимиты на прокси |
| Токен Telegram попадает в лог Alertmanager при ошибке сети (часть URL Bot API) | поведение Alertmanager | лог доступен только root; у тестовой среды отдельный бот |
| Файлы паролей vault на управляющей машине открытым текстом | так работает `vault_identity_list` | права `0600`, каталог вне git; разделение паролей защищает при утечке одного файла, но не при доступе к машине |
| CA не перевыпускался после хранения `ca.key` на сервере | признаков компрометации нет; перевыпуск = пересборка приложения у всех | ключ вынесен с сервера, резервные копии хостера, сделанные до выноса, удалены |
| Прокси читает секреты из `.env`, а не из файлов | нужно изменение приложения | `.env` — `root`, `0600`; сервер без лишних пользователей |
| Роль ufw только добавляет правила | особенность роли | удаление — ручной шаг в плане работ |
| Наблюдаемость MaxApoc на рабочем сервере зависит от стека `hobot-metrics` | памяти не хватает на второй стек | см. [ADR-006](DECISIONS.md#adr-006) |

## Перед публикацией репозитория

- Проверка истории на утечки: адреса, имена приватных репозиториев, удалённые из отслеживания файлы (логи) остаются в истории.
- Поиск по изменениям перед каждым коммитом: токены Telegram и GitHub, ключи шлюзов, заголовки закрытых ключей; положительный контроль шаблона на расшифрованном vault.
- В модуле B — автоматическая проверка (сканер секретов в pre-commit и CI).
